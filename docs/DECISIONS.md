# Decisions: SQL Server CDC Data Extractor

Этот документ фиксирует принятые продуктовые решения, чтобы дальше быстро и однозначно дописать PRD.

## Принятые решения

1) **Выходные данные: `changelog`**
- Экстрактор отправляет события изменений (insert/update/delete) на downstream-сервис.
- Downstream отвечает за запись в S3 (CSV) и (если нужно) сборку “актуального состояния” из changelog.

2) **Интеграция: HTTP API + чанки + `commit(manifest)`**
- Экстрактор отправляет данные порциями (chunks).
- После отправки всех чанков для “набора” вызывается финальный `commit` с манифестом, который атомарно публикует результат.
- Детали API (эндпоинты, безопасность, ошибки, лимиты/MaxBytes, idempotency) выносятся в отдельный документ `APIs.md`.

3) **Идентичность порции данных (idempotency key)**
- Ключ: `table` + `(from_lsn,to_lsn)` + `chunk_no`.
- `commit` должен быть идемпотентным для одного и того же `(table, from_lsn, to_lsn)`.

4) **CSV для дельт: служебные колонки включены**
- Минимум: `_op` (I/U/D), `_lsn`, `_seqval`, `_ts` (время события, если доступно/однозначно).
 - Как маркируется initial snapshot в CSV (например `_op=SNAPSHOT` или отдельный dataset type) — будет определено в `APIs.md`.

5) **Schema manifest: JSON**
- Для каждой таблицы формируется JSON с колонками (имя, SQL-тип, nullable, длина/precision/scale где применимо) и ключами (PK/unique).
- Поля `computed/identity/collation` не требуются в MVP.

6) **CDC cleanup/retention: делает экстрактор**
- Экстрактор проверяет prerequisites (SQL Agent включен, права есть).
- Экстрактор включает CDC на БД/таблицах (при первичной настройке) и настраивает retention/cleanup job.
 - Значение по умолчанию: 7 дней (конфигурируемо).
 - Политика применения: экстрактор обеспечивает минимум 7 дней retention; не понижает retention, если на сервере уже выставлено больше.

7) **Расписание и конкуренция**
- План: 3 прогона в день: 08:00, 12:00, 18:00 (локальное время сервера).
- Жесткое правило: параллельные прогоны запрещены (single-instance lock).

8) **IPC менеджер <-> сервис**
- Транспорт: Windows Named Pipes.
- Протокол: JSON-RPC поверх stream.
- Библиотека: StreamJsonRpc (Microsoft).
- Логи: подписка/notifications (server->client).

9) **Выбор таблиц через Windows UI, хранение выбора локально**
- Windows приложение (installer + конфигуратор + менеджер статусов) записывает выбор таблиц и параметры в локальный конфиг/state на сервере.

10) **Таблицы без уникального ключа: fallback “small table snapshot”**
- Если у таблицы нет PK/unique index и она небольшая, допускается стратегия: периодически делать полный snapshot (каждый прогон).
- Для больших таблиц без уникального ключа: блокировать/явно требовать решения (например добавить unique index).
 - “Small table” по умолчанию: ~1000 строк (конфигурируемо).

## Открытые вопросы (минимум, чтобы завершить PRD)
1) `APIs.md`: точные эндпоинты, безопасность, обработка ошибок, лимиты/MaxBytes, формат manifest/commit.
2) Стратегия консистентности snapshot+CDC (выбор конкретного алгоритма LSN-гарантий для MVP).
3) Политика “CDC gap”: что делаем, если `last_processed_lsn` старее минимального доступного LSN из CDC (требуется re-bootstrap).
