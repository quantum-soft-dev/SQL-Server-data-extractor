# Фаза 2: Production Hardening

## Overview
Сделать MVP пригодным для продакшена: стабильная установка/обновления, надежность при сбоях, полноценная наблюдаемость, безопасность, UX-улучшения менеджера, и “операционные” гарантии.

## Цели
1) Свести риски потери данных/дубликатов к управляемым, повысить предсказуемость.
2) Упростить поддержку: диагностика, экспорт логов, понятные статусы и рекомендации.
3) Закрыть безопасность: хранение токенов/секретов, права, аудит.

## Scope (входит)
1) Installer/upgrade:
   - MSI/инсталлер, сохранение конфигов/state при обновлении;
   - корректная регистрация Windows Service.
2) Надежность и восстановление:
   - строгие ретраи и классификация ошибок (transient vs terminal);
   - гарантии идемпотентности на уровне dataset/chunk;
   - восстановление после рестарта сервиса (без ручных правок state).
3) Наблюдаемость:
   - структурированные логи + ротация + экспорт из UI;
   - метрики (минимум: длительность batch, строки/байты, lag по LSN, ошибки, ретраи);
   - улучшенный прогресс по таблицам (ETA/скорость).
4) Безопасность:
   - OAuth Device Flow: хранение refresh token (DPAPI), rotation (если требуется);
   - TLS настройки к SQL Server и к downstream;
   - ACL на Named Pipes.
5) UX менеджера:
   - “проверить подключение” и prerequisites чеклист;
   - статусы и рекомендации при CDC gap (увеличить retention/частоту прогонов);
   - управление расписанием (в UI).
6) CDC/SQL Server:
   - устойчивые проверки “CDC на таблице/базе включен”;
   - политика “не понижать retention, повышать до минимума”.

## Out of scope
1) Поддержка нескольких источников (multi-source) в одной установке.
2) Распределенная обработка и горизонтальное масштабирование.
3) Replica режим.

## Deliverables
1) Production-ready билд (installer + service + app).
2) Runbook: troubleshooting, коды ошибок, частые проблемы.
3) Расширенный `APIs.md` (идемпотентность, error taxonomy, токены).

## Definition of Done / Acceptance
1) После обновления версии конфиг и state сохраняются и сервис стартует без ручных действий.
2) При сетевых сбоях и рестартах сервис корректно продолжает работу без пропусков LSN.
3) UI дает пользователю пошаговую диагностику и понятные сообщения (без “голых” exception).
4) Токены/секреты не лежат в открытом виде.
